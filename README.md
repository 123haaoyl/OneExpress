# 批次轨迹维护工具

这是一个本地单页工具，用来按批次维护物流轨迹。直接打开 `index.html` 即可使用，数据保存在当前浏览器本地。

## 已支持功能

- 按批次新建、维护、搜索物流轨迹
- 拆分子批，状态一致后可拖拽合并回主批
- 合并前确认，若两个批次节点不同会提醒
- 深色 / 浅色主题切换
- 轨迹模板维护，支持 `{origin}`、`{destination}`、`{ems}` 变量
- CSV 导入、推送 CSV 导出
- JSON 备份 / 恢复
- Supabase 云数据库同步配置

## 推荐流程

1. 每天收到订单后，按真实处理批次新建批次。
2. 同一批状态一致就放在同一个批次里；如果一部分货物状态不同，使用“拆分当前批次”拆成子批。
3. 每次有真实节点发生时，在批次详情里选择“当前节点”和“发生时间”，检查轨迹内容后点击“加入轨迹”。
4. 复制“批量推送内容”到推送系统。推送成功后点击“标记全部已推送”。
5. 每天下班前在“导入导出”里下载 JSON 备份。

## 云数据库

“导入导出”页里提供 Supabase 建表 SQL。建表后填写：

- Supabase 项目 URL
- anon key
- 表名，默认 `tracking_tool_state`
- 记录 ID，默认 `main`

保存配置后可手动上传 / 读取，也可以勾选自动同步。

注意：纯前端页面不能安全保存数据库管理员密钥，因此这里使用 Supabase anon key + RLS 策略。多人账号、权限隔离、操作审计建议后续加登录或后端代理。

## 模板变量

- `{origin}`：始发地，默认 `CHINA`
- `{destination}`：目的地，例如 `AUSTRALIA`
- `{ems}`：输出为 `#ems_number#`，用于你们推送系统自动替换中国邮政单号

## CSV 导入格式

支持表头：

```csv
批次名称,票数,目的地,当前节点,时间,单号
2026-06-14 澳洲线 A批,1500,AUSTRALIA,中国仓处理,2026-06-14 12:53,AUS001;AUS002
```

如果一批里有很多单号，建议先只填批次和票数，具体单号可在批次详情里粘贴维护。

# 批次轨迹维护工具

这是一个本地单页工具，用来按批次维护物流轨迹。直接打开 `index.html` 即可使用，数据保存在当前浏览器本地。

## 已支持功能

- 按批次新建、维护、搜索物流轨迹
- 拆分子批，状态一致后可拖拽合并回主批
- 合并前确认，若两个批次节点不同会提醒
- 深色 / 浅色主题切换
- 轨迹模板维护，支持 `{origin}`、`{destination}`、`{ems}` 变量
- CSV 导入、推送 CSV 导出
- JSON 备份 / 恢复
- Supabase 无感自动同步
- 回收站，防止误删批次

## 推荐流程

1. 每天收到订单后，按真实处理批次新建批次。
2. 同一批状态一致就放在同一个批次里；如果一部分货物状态不同，使用“拆分当前批次”拆成子批。
3. 新建批次时粘贴单号 / 转运号，票数会自动按清洗后的单号数量计算，空行会忽略。
4. 每次有真实节点发生时，在批次详情里选择“当前节点”和“发生时间”，检查轨迹内容后点击“加入轨迹”。
5. 复制“推送内容”到推送系统。推送成功后点击“标记全部已推送”。
6. 每天下班前在“导入导出”里下载 JSON 备份。

## 无感实时同步

这个版本没有手动同步按钮。打开工具时会自动读取云端数据；你修改批次、轨迹、模板后，会自动上传；其他电脑打开同一份工具会定时拉取云端更新。

第一次配置：

1. 在 Supabase SQL Editor 执行 `supabase-schema.sql`。
2. 复制 `config.example.js` 为 `config.js`。
3. 在 `config.js` 填入 Supabase 项目 URL 和 anon key。
4. 用本地服务或部署后的网页打开 `index.html`。

`config.js` 会随仓库提供默认配置；部署时请确认里面是当前环境可用的 Supabase URL 和 anon key。

注意：直接用 `file://` 打开时，部分浏览器可能会限制云端请求。建议用本地静态服务或 GitHub Pages / Netlify 等网页部署方式打开。

纯前端页面不能安全保存数据库管理员密钥，因此这里使用 Supabase anon key + RLS 策略。多人账号、权限隔离、操作审计建议后续加登录或后端代理。

## 防误删机制

- 删除批次不会直接删除，而是移入“导入导出 > 回收站”。
- 在回收站里可以恢复批次，也可以彻底删除。
- 彻底删除后不能从回收站恢复；需要额外留档时，请手动下载 JSON 备份。

## 模板变量

- `{origin}`：始发地，默认 `CHINA`
- `{destination}`：目的地，例如 `US`
- `{ems}`：输出为 `#ems_number#`，用于你们推送系统自动替换中国邮政单号

## CSV 导入格式

支持表头：

```csv
批次名称,票数,目的地,当前节点,时间,单号
2026-06-14 美国线 A批,2,US,中国仓处理,2026-06-14 12:53,US001;US002
```

如果一批里有很多单号，建议先只填批次和票数，具体单号可在批次详情里粘贴维护。
